# Sprint-Review

## How do I interpret user needs and implement them into a program, and how does writing user stories help with that?

Interpreting user needs requires defining what functionality and features the user base is requesting and determining if and how these features should be implemented into a project. The best user feedback still requires much consideration for how changes and features will impact a project's functionality, security, and future development. User stories assist in defining desired functionality in a more concise and clear way. The "As a {type of user}, I want to {do some action}, so that {benefit or result}" format helps to frame feedback and user needs in a more definable way.

## How do I approach developing programs, and which Agile processes do I want to carry into future work?

I approach developing programs by mapping out how the system or portion of a program will be structured. Some things I consider are: What inputs and outputs are necessary for the program to function? How should functionality be split up to maintain good separation of concerns and code maintainability? How does the data flow through the system, and which components need to interact to achieve the ultimate goal of the system? Once the program design is mapped out, it becomes much easier to design, implement, and change the component parts without needing to redesign the program as a whole. An Agile process that I took away from SNHU's Software Development Life Cycle course is the "Information Radiator" concept. Whether developing a personal project or working as a team, an open display of the project's status and its relevant information and design choices helps maintain focus and keeps the scope of the system design in mind while developing smaller parts of the system.

## What does it mean to be a good team member in software development?

A good team member strives for technical excellence while also supporting and collaborating with team members to support the project at large. A good team member also holds themselves accountable for the success of a project and makes decisions that support the team's productivity and effectiveness. Finally, a good team member is respectful in every interaction while being open and honest about the project and the work being done.
